# Refines that do what was asked: the measurement, 2026-10-09

Did #136's changes make refines do what was asked? This compares the refine agent **before #136** with the agent **after** it, on 18 refine tasks scored three ways.

## What changed in the agent

- **Goals:** the refine prompt asks the agent to turn the request into checkable goals. It passes the ones code can check to `propose_changes`, which sends back a change that misses one.
- **More information:**
  - in a refine, `analyze_deck` compares the proposal with the saved deck, and lists each card's mana value and roles and what the pool has left by role
  - a refine-only `find_by_role` tool lists the pool's cards with a role
- **Drafts are unchanged,** in their prompt, tools and analysis. #159 tracks offering role search in drafts.

## How it was measured

- **The tasks:** 18 refines.
  - T09-T14 cover vaguer requests such as "add more removal and cut the weakest cards".
  - T15-T26, added for this, have exact numeric goals such as "cut down to 38 lands and add four card draw spells".
  - Each starts from a deck Sonnet or Haiku drafted, in a pool with role tags.
- **Before:** the agent at `6eb5739` (before #136), run with today's eval code so both sides are scored the same way.
- **After:** the agent at `410f90c`.
- **Three measures:**
  - **Goals checked by code:** pass or fail, with no grader involved.
  - **Fit:** Opus 5.5, under the rubric, shown the starting deck and the change.
  - **Pairwise:** Opus compares the two changes side by side, twice with the order swapped. A preference counts only if it holds both times.
- **The grader's own noise was measured first:** the same 12 decks were graded twice ([report](2026-10-09-grader-consistency.md)). Fit matched 11 times in 12, so most of the noise in refine scores is the agent, not the grader.

- **Every measure points the same way, and none is conclusive.** The fit interval still includes zero, and 8-4 on the decisive pairs could be chance.
- **The change costs nothing.** Turns and cost per refine are unchanged.
- **There's a ceiling.** Before #136, the agent already met 94% of goals, with mean fit 4.06, so most tasks had little room to improve. The gains are on the vaguer requests: T09, T10, T14 and T17 each rose a point of fit.
- **#136's done-when is met:** T09 scores fit 3 and T10 scores 4. Drafts are unchanged by construction, so they're no worse.

## What went wrong on the way

- **The grader couldn't see a refine's change.** It saw only the final deck, so it marked refines down for flaws the starting deck already had. Refines are now graded with the starting deck and the change shown.
- **The first "after" run was spoiled by a bug in the goal schema** ([`2026-10-09T185229-sonnet.json`](../runs/deck_tasks/2026-10-09T185229-sonnet.json), kept as evidence).
  - **What happened:** the agent stated "removal up" without a count, the validator rejected every `propose_changes` call, and the agent never recovered. The run had 182 tool errors, refines took up to 30 turns, and 5 were skipped on budget.
  - **The fix:** a count goal with no number now means at least one, and the field descriptions now name every kind that uses each field.
  - **The cost:** $2.77, then a $0.21 smoke test before re-running.

## Takeaways

- **Measure the grader before the agent:** it showed where the noise was, and what more tasks could and couldn't fix.
- **Code-checked goals are the cheapest, sharpest signal** where a request has numbers in it.
- **A tool schema the model fails to fill can wreck a run.** A smoke test of two tasks costs little and would have caught it.
