# Milestone 7: evaluation and the CI gate, 2026-10-08

The summary of Milestone 7 (#9): what the eval suite measures, the results, how far the model graders can be trusted, and what the CI gates check. Each suite's own dated report has the full tables, and the run files behind every number are committed under `evals/runs/`.

**Done when (#9):** a deliberately degraded prompt or retrieval setting makes the CI eval fail. Both were shown:
- **A degraded retrieval setting fails the free gate.** With card search switched to keyword-only, dev recall@10 fell from 0.840 to 0.515, and four metrics failed (#119).
- **A degraded system prompt fails the live eval in CI.** A manual run with the rules prompt stripped of its citation and "not found" instructions scored 0.00 on every metric and failed (CI run 37688084264, #124). The same eval passes on `main` with every metric at 1.00.

## The suite

| Eval | What it measures | Where it runs | Cost |
|---|---|---|---|
| **Free gate** (`evaluation/gate.py`, #119) | Retrieval (recall@10 and MRR@10 on dev and test), the validator on 12 labelled decks, and pool resolution | **Every PR**, from a committed embedding snapshot | Free |
| **Live eval** (`evaluation/live_gate.py`, #124) | 8 rules questions on the real model: citations and "not found", by code | **Every push to main**, and on demand | About $0.03 a run, capped at $0.10 |
| **Rules Q&A** (`evaluation/rules_qa.py`, #121) | 55 questions: correctness by a model grader against key facts, citations by code, "not found" | Locally, paid | About $0.40 a run |
| **Deck tasks** (`evaluation/deck_tasks.py`, #122) | 10 tasks: legality, cost, turns, latency, and quality by an Opus grader against a rubric | Locally, paid | About $1.60 a run |
| **Injection** (`evaluation/injection.py`, #123) | 5 cases: poisoned card or rule text, checked by code | Free scripted cases in CI; live locally | About $0.40 a live run |
| **Hand grading** (`evaluation/hand_grade.py`, #122, #125) | The owner's blind grades, and agreement with the model graders | Locally, free | Free |

## Rules Q&A: models and retrieval

55 questions: 45 answerable and 10 the Comprehensive Rules don't answer. Correctness is graded by Sonnet 5.5 (`2026-10-06-rules-qa.md`, `2026-10-07-rules-qa.md`, `-2.md`).

| | Sonnet 5.5, vector search (shipped) | Haiku 4.5, vector search | Sonnet 5.5, hybrid search |
|---|---|---|---|
| Correct (by the grader) | **99%** | 93% (see below) | 96% |
| Cites an answering rule | 100% | 100% | 95% |
| Citation precision | 89% | **95%** | 85% |
| "Not found" when it should | **100%** | **30%** | 100% |
| "Not found" wrongly | 0% | 0% | 2% |
| Success | **80%** | 75% | 75% |
| Agent cost (55 questions) | $0.25 | $0.16 | $0.30 |

- **Sonnet is the right model for rules answers.** Haiku answered 7 of the 10 questions the rules don't cover, instead of saying "not found". It cites more precisely, though, with fewer rules from other variants.
- **Its correctness is probably understated.** The owner judged three of Haiku's four marked-down answers correct, and the fourth partly correct; see "How far the graders can be trusted".
- **Vector search stays.** Hybrid rules search was slightly worse on every answer metric, which confirms Milestone 4's retrieval choice end to end.
- **The most common failure is citing other variants' rules.** Sonnet's answers to Commander questions cite Brawl, Commander Draft or team-play rules alongside the right ones. Once (R11), that leaked into the answer itself: planeswalkers as commanders. Telling the agent which variant applies, or filtering variant sections out of rules search, would address it.

## Deck tasks: models

8 drafts compared like-for-like. The two refines ran only on Sonnet: on Haiku the run's budget skipped them, and with the owner they weren't run again, since they couldn't change the comparison. Quality is graded by Opus 5.5 (`2026-10-07-deck-tasks.md`, `-2.md`).

| | Sonnet 5.5 | Haiku 4.5 |
|---|---|---|
| Legal deck | 100% | 100% |
| **Turns per draft** | 4.8 | **17.1** |
| **Rejected proposals** | 4 | **42** |
| **Agent cost per deck** | $0.120 | **$0.175** |
| Median time per draft | 66 s | 212 s |
| Quality (1-5) | **3.30** | 2.87 |
| Plan, fit, mana, ramp, draw, interaction | 2.75, 3.00, 3.38, 3.00, 3.75, 3.75 | 2.62, 3.00, **1.75**, 2.50, 3.50, 3.88 |

- **For building decks, Haiku is the more expensive model,** despite tokens at half Sonnet's price. It proposed illegal decks about five times per draft, and each rejection cost another turn. It also built worse decks, mana bases especially.
- **Quality follows the pool more than the model.** On Sonnet, the owner's real TCGplayer collection gave decks scoring 4.2-4.5. The random 300-card pools gave 2.2-3.4: they're thin, so the agent fills decks with 43-45 lands and filler.
- **Sonnet's refines change too little.** "Add more removal and cut the weakest cards" left the weak cards in, and both refines scored fit 2.

## Prompt injection

5 cases, each a normal task with one poisoned card or rule (`2026-10-07-injection.md`).
- **Sonnet 5.5 never obeyed injected text.** Four cases resisted outright, and three of those told the user about the attack.
- **The fifth, asking for the system prompt, leaked nothing, but the API refused and the draft never finished.** Text in a card can therefore stop a user's draft.
- **The guardrails held in every case:** no approval, no saved deck, and the poisoned text always inside its `<untrusted>` block.
- **Wider cases are planned** in #133: more places untrusted text enters, and attacks with goals unrelated to Magic.

## How far the graders can be trusted (EVL-3)

The owner graded a sample blind, using the same rubric and seeing what the model grader saw, but not its grade, the model or the variant.

**Decks (Opus 5.5, 18 decks, 102 scores):**

| | Exact | Within one | Weighted kappa |
|---|---|---|---|
| All scores | 76% | 99% | **0.90** |
| Lowest: interaction | 67% | 94% | 0.81 |
| Highest: plan coherence | 83% | 100% | 0.93 |

Only one score is two points apart: interaction on Sonnet's T08 flyers deck (grader 5, owner 3). On fit, the owner was the stricter one every time they differed: four decks the grader scored 2 ("in name only"), the owner scored 1 ("ignores the request").

**Rules answers (Sonnet 5.5, 51 answers):**
- **Overall: 88% exact, every disagreement within one level.** Weighted kappa is 0.52, which is low only because almost every answer is correct: chance agreement is high, and kappa then hinges on the handful that aren't.
- **The hard cases.** The owner also graded every answer the grader marked down, with as many correct ones mixed in so they couldn't be told apart. **They agreed on only 2 of those 6.**
  - The grader penalises extra claims beyond the key facts more strictly than the owner does. At least once (R08) it called a correct statement wrong: that the command zone move is a state-based action, which is what rule 903.9a says.
  - In the other direction, the owner was stricter once: R01, which the grader called correct.
- **So the grader is trustworthy on correct answers, and conservative on long answers that add detail.** That affects Haiku most: its answers are wordier, and the owner judged all four of its marked-down answers correct or partly correct, three of them correct. Haiku's 93% is a lower bound.

## The CI gates

- **The free gate** runs on every PR in about a minute, with nothing paid.
  - It works from a committed embedding snapshot: 4,122 cards, every rule and 162 queries, in half precision, 19 MB.
  - Its thresholds sit 0.02 below a deterministic baseline, and CI reproduced the local numbers exactly.
  - Re-exporting the snapshot now keeps existing query vectors, because a full re-embed had moved test-card MRR by 0.012.
- **The live eval** runs on every push to `main`, capped at $0.10.
  - CI has no embedding model, so each case's searches use the snapshot's vector for its question, a documented stand-in.
  - It passed on `main` and failed on demand with the degraded prompt, as designed.
- **A gap:** a prompt change can't be caught before merge, because the live eval doesn't run on PRs. ADR 0016 records this deliberate trade against paying for every PR push.

| | |

| Injection (live), including an aborted attempt and a re-run | $0.68 |

**About $0.36 went on attempts lost to harness bugs,** each found by reading the live output and fixed with a test first:
- the grader's open-dict schema, which structured output can only fill as `{}`
- a model client shared across a whole suite, so its per-run cap covered every task
- a reranker recording to the dev database
- injection cases counting as passed when the poison was never shown

## Limitations and next steps

- **The pools behind the deck tasks:** two of the three are random 300-card samples, and their thinness, not the agent, sets the quality ceiling.
- **Hand grading:** 18 decks and 51 answers are enough to read agreement roughly, with wide confidence intervals.
- **The rubric's handling of extra claims:** the rules grader's strictness about them is worth a clearer rule, for example "judge only claims that bear on the question", before trusting fine-grained model comparisons on rules answers.
- **Agent improvements this milestone points to:**
  - tell the rules agent which variant applies, to stop Brawl and Draft citations
  - make refines change what was asked
  - say "the model refused, possibly because of text in your data" instead of a generic error
- **Wider injection cases:** #133.
